# Rule 08 — Clinical Safety and Data Integrity

Mistakes in this system can harm patients. The system **supports clinicians; it never makes clinical decisions on its own.** When a requirement touches these areas and the spec is not explicit, stop and ask the owner (AGENTS.md section 7).

## Patient identity

- Every patient has a unique, system-generated ID (UUID) and a human-friendly Medical Record Number (MRN), generated by the database (sequence-based, format set by the Phase 1 spec).
- Wrong-patient errors are the top risk. Screens and printouts that act on a patient show at least two identifiers.
- **Duplicate patients are never deleted.** Duplicates are merged by linking: the merge is reversible, keeps every record of both, and is fully audited.
- Never guess or auto-match patients. Duplicate detection suggests candidates; a human decides.

## Never infer or silently change clinical data

- No auto-correction, auto-completion, rounding, or defaulting of clinical values (vitals, doses, results, diagnoses).
- Missing data stays missing (null). Do not substitute zero, "N/A", or a default that looks like a real value.
- Every clinical record shows who entered it and when.

## Amendments and history

- Clinical records are **append-only in effect**: a correction creates a new revision with a reason, and the original remains viewable.
- Never overwrite a result, note, prescription, or diagnosis in place.
- Voiding requires a reason and is audited (rule 03, rule 05).

## Time

- Record both `occurred_at` (when the event happened) and `recorded_at` (when it was entered). Clinical events are often entered late.
- Store UTC; display in the hospital timezone. Never store local time without an offset.
- Never accept future timestamps for events that already happened, unless the spec allows scheduling.

## Units, quantities, and numbers

- Every measured value stores the numeric value **and** an explicit unit. No units hidden in free text.
- Use `numeric` types, never floating point.
- No unit conversion unless it is an explicitly specified, unit-tested function.
- Doses are structured (amount, unit, route, frequency, duration), not only free text. Free text may be added as a note.

## Medical coding and reference data

- Diagnoses: ICD-10 code + code-system version + display text stored together, so old records remain interpretable. Keep a local copy of the code list; no live external lookups.
- Lab tests: LOINC-compatible code fields (optional locally, but the schema must allow them). Drugs: ATC classification and a local drug catalog; RxNorm-compatible fields where useful.
- Model data so it can map to HL7 FHIR resources later (Patient, Encounter, Observation, MedicationRequest, MedicationDispense, etc.), but do not implement FHIR APIs before the roadmap says so.
- Reference data (drugs, tests, price lists) is deactivated, never deleted, so historical records stay intact.

## Alerts and decision support

- Allergy, interaction, and duplicate-therapy checks must **never silently pass**. If a check cannot run (missing data, no interaction data source), the UI must say "check not performed" rather than showing nothing.
- Alerts that a clinician overrides require a coded reason and are audited.
- Do not invent or hardcode clinical rules, drug interaction data, dosing limits, or reference ranges. They come from the owner-approved spec or an owner-approved data source.

## Dispensing and stock (pharmacy)

- Dispense from batches with expiry dates; expired batches are blocked. Default dispensing order is FEFO (first-expired, first-out) unless the spec says otherwise.
- Stock never goes negative. Stock changes are recorded as movements (receipt, dispense, adjustment, return, write-off), never as edits to a quantity field.
- Dispensing verifies the patient, the prescription status, and remaining quantity in one transaction with an idempotency guard against double-dispensing.
- Controlled substances need their own register and stricter permissions, defined in the pharmacy spec.

## Results and orders

- A result is linked to exactly one order and one patient. Corrected results supersede, not replace.
- Critical or abnormal flags come from the approved reference ranges, never guessed. When no range exists, show no flag and no fabricated "normal".

## Money

- Amounts are exact decimals in a single configured currency per deployment (multi-currency is out of scope unless specified).
- Payments and refunds are ledger entries. Refunds are reversals, never edits or deletions.
- Invoices, once issued, are immutable. Changes happen through credit notes or reversals.

## Privacy

- Minimum necessary: show users only the patient data their permissions allow.
- Printouts and exports containing patient data are audited and carry the printing user and time.
- Test and demo environments contain only synthetic data.
